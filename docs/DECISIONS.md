# Decisions

Choices made where BRIEF.md is silent or ambiguous. Newest at the bottom.

1. **Branch.** The cloud session is pinned to branch `claude/serene-darwin-imby77`; it plays the role CLAUDE.md gives `poc`. Each milestone is also pushed as a snapshot branch `milestone/mN` with a PR against `main`, so every milestone gets its own PR while work continues.
2. **Proxy base meshes moved into S0.** The fixture pack (S0) and the Build-screen preview (S1) both need the base meshes, so `scripts/make_proxy_base.py` and `scripts/check_base_mesh.py` are built first.
3. **Python layout.** One project venv (`.venv`, Python 3.12) for API, worker, mock server and tests. Blender scripts run as subprocesses under the bpy interpreter (`PETPOP_BPY_PYTHON`, default `/opt/bpy/bin/python`, Python 3.11 + `bpy` 5.0), mirroring the production "Blender via subprocess" design. Shared contract models and the rule-based parser live in `backend/core/` and are imported by the mock server.
4. **Rendering engine.** Workbench and EEVEE need EGL/GPU and crash headless; all mock renders use Cycles on CPU at low samples.
5. **PetSpec enumerations.** Closed sets chosen where Section 3 lists none: body.size tiny/small/medium/large, build slim/standard/stocky, a 12-name coat palette (custom hex maps to the nearest name), 12 patterns (the Build screen shows the 8 that fit the species), markings white_blaze/white_socks/white_chest/dark_mask/points, 6 eye colours, 5 nose colours. `overrides` only allows `ears.asymmetry`. `ears.tufted` (cat) drives the `ear_tuft` morph.
6. **Cat morph list (spec gap).** Section 10 says "cat: 12, no brachy split, add ear_tuft", which does not add up from 15. Chosen: drop `brachy`, `ear_drop`, `tail_curl`, `leg_len`, add `ear_tuft` (12). `vocab.species_substitutes` maps the dropped dog targets onto cat ones. To confirm with whoever builds the hand-made cat mesh.
7. **Morph weights** range -1..1 with 0 = the base mesh; slot contributions are summed and clamped. `ears.asymmetry` is prompt-only in the PoC (no per-side morph exists in Section 10).
8. **Units.** Base meshes, wraps and print meshes are in millimetres (1 Blender unit = 1 mm), 90 mm tall; GLBs keep those units and the viewers fit the camera to the bounds.
9. **Region masks.** Pattern and marking regions are baked once per base mesh into two UV-space RGBA masks (`mask_a.png`, `mask_b.png`). The preview shader, the mock renders and the albedo bake read the same masks, so swatches, preview and output agree.
10. **One contract router.** `backend/core/contract.py` defines every `/api/v1` route once against an implementation protocol; the mock server and the backend mount it, so their OpenAPI is identical by construction and `data/schema/openapi.json` is generated from it (`make openapi`), with a drift check in gate-0.
11. **Mock script selection.** The mock server picks a script by pet name (`Slowpoke`, `Oops`, `Plan B`), otherwise `MOCK_SCRIPT` (default `normal`), so every kiosk state is reachable from the touchscreen with no headers.
12. **Fixture pack v1** is produced by the numpy/trimesh stand-in (`make_fixtures.py --lowfi`, `fidelity: low`); S2 regenerates it from the real mock-mode pipeline. About 32 MB.
13. **GPU gates.** Gates 3 to 5 exit 0 after printing `gate-N: SKIPPED (needs GPU)` in mock mode and never print PASSED; gate-6 likewise skips (needs the kiosk screen and GPU).
14. **MSW parser.** Standalone mode (`VITE_MOCK=1`) uses a small TypeScript synonym matcher over `vocab.json` instead of the Python rule parser; it is only for demos without a backend.
15. **Visual directions.** Three Storybook themes over the same components, selected with the toolbar (kiosk: `?theme=`): `candy` (default: warm paper, orange dog / violet cat accents, 36 px radius), `studio` (neutral greys, tight radius, product-shop feel) and `toybox` (dark indigo, saturated yellow/teal, chunky shadows). The kiosk ships `candy` until the touch review picks one.
16. **Build layout.** Portrait 1080x1920: selectors scroll in a left column, the live preview is a fixed 400 px column on the right, labelled "Preview". The preview albedo is painted on a 256 px canvas from the UV region masks (same rules as the bake) and the morph weights come from a TypeScript port of `morph_weights`; both update in well under 100 ms.
17. **Kiosk frame.** The SPA renders a fixed 1080x1920 canvas scaled to the window; R3F canvases measure with `offsetSize` so the CSS scale does not shrink the drawing buffer. Tests run at 540x960 with touch enabled.
18. **Idle policy overrides.** `?idle=&countdown=` (seconds) override the session's idle policy for tests and demos; production uses the API's 90 s + 15 s.
19. **Attract loop content** comes from the bundled fixture pack (the first six pets), so the attract screen works with no API call; S5 can swap in real demo figurines.
20. **Fixture GLBs are Y-up** (glTF convention, front +Z), matching the Blender exporter; print meshes stay Z-up in millimetres.
21. **make dev queue and events.** The brief pairs "two Python processes" with "in-process asyncio queue + fakeredis", which cannot span processes. `LocalBus` uses the SQLite `jobs` table as the queue (atomic claim of the oldest queued row, one running job at a time) and a `job_events` table that the API tails for WebSockets. `RedisBus` (arq + Redis lists) implements the same interface for the GPU host. `PETPOP_EMBED_WORKER=1` runs the worker thread inside the API process (tests, smoke runs).
22. **Stage signature.** Stages are `run(job_id, spec, manifest, *, ctx)`: the brief's `(job_id, spec, manifest)` plus a keyword-only context carrying the store, adapters, progress callback and settings. Stages read inputs only through `ctx.get()` (the artefact store) and write through `ctx.put()`.
23. **Quality profiles.** `PETPOP_PROFILE` = `full` (brief values: 1024/768 px, 2048 albedo, 0.15 mm voxels, 250 k tris), `dev` (default in mock mode, ~45 s per job on 4 CPU cores), `fixture` (fixture pack, ~3 MB per pet) and `test` (contract, pipeline and regression tests). Mock-mode stage timeouts are the brief's times 6 because Blender runs on CPU.
24. **Mock texture source.** In mock mode the views are renders of the same flat colours, so the mock texture backend paints the PetSpec colours over the region masks in the fixed UV layout instead of projecting the views. Per-region colour correction toward the PetSpec hex values runs on generated textures (real mode).
25. **Wrap details.** Coarse fit = ICP (similarity) + landmark pull propagated with an RBF (the Surface Deform role); fine fit = shrinkwrap by projection along normals (both directions, 3 mm limit) on the body shell only, three passes of rising strength. Ears and tail keep their morph shape with a rigid fit (Section 14 mitigation). Validation is relative to the morphed template (the wrap must not add self-intersections). Multires is not used on the ~6 k-quad proxies.
26. **Blender container.** The worker image bundles the `bpy` wheel (Python 3.11) and runs the Blender stages as subprocesses with Cycles on CUDA, instead of a separate `blender` service; the compose file therefore has api, worker, comfyui, ollama, postgres, redis, minio.
27. **Print mesh.** Shells, accessories and the base disc are joined, voxel-remeshed, the socket is cut with exact booleans, decimated, then cleaned (merge, fill pin-holes, drop loose fragments < 0.5 %); a trimesh repair pass removes boolean slivers before STL/3MF. Accessories are thickened in the library so nothing prints under 1.5 mm, and the collar sinks slightly into the neck.
28. **Proxy morph fixes.** `leg_len` stretches everything below the leg tops continuously (no fold), `fluff` pushes along smoothed normals by 1.8 mm, and tail roots sit inside the body so the print is one solid. These are proxy-only; the hand-built meshes define their own shape keys.
29. **Fixture pack v2** is regenerated by the real mock-mode pipeline with the `fixture` profile; intermediates (control renders, wrapped mesh) are pruned to keep it near 30 MB.
30. **Accessory UVs.** Accessories carry their own small UV islands but are flat-coloured materials in the GLB; `figure_uv.obj` (the painter layout) contains the pet only.
31. **M2.5 GenAI profiles.** `GENAI_PROFILE` replaces `PETPOP_MODE`; the mode, quality presets (`PETPOP_QUALITY` replaces `PETPOP_PROFILE`), stage timeouts, pacing references, expected timings, residency rules, endpoints, model ids and adapter backends all come from `config/genai/<profile>.yaml`, validated against `data/schema/genai-profile.schema.json`. `tests/unit/test_host_agnostic.py` scans the worker's string literals for URLs, hosts, ports, model files, model names and workflow file names.
32. **Manifest 1.1** adds a required `genai` block: profile name, version and file hash, host and accelerator, adapters, every model id the job may use with its pins from `models.yaml`, and the quality preset. Workflow versions are recorded as `<version>-unvalidated` until a workflow is validated.
33. **Workflow bindings.** API-format graphs contain no PrimitiveNodes (they are UI-only), so each generated workflow carries `meta.inputs` (named value -> [node id, input]), `meta.outputs` (name -> SaveImage/SaveGLB node), `meta.optional_nodes` (bypass rules, e.g. the LoRA until it exists) and `meta.required`. Model file names are bound from the profile at run time; node ids are generated by `scripts/make_comfy_workflows.py`. Node classes and inputs were read from each pack's source at the pinned commit.
34. **Background matting** of generated images is done by the worker (`white_key`: largest non-white component, holes filled, re-centred), not by a BiRefNet node, to keep custom-node dependencies minimal; the workflows render on a plain white background.
35. **Texture by projection** is the default on every profile, including mock: the four views are registered to the wrapped mesh by silhouette bounding box, occlusion-tested (pet and accessories) against a z-buffer, blended by max(0, n.v)^2, texels no view sees fall back to the PetSpec flat colours, then per-region colour correction and seam padding. Hunyuan3D-Paint (`hy_paint`) is allowed only on `nvidia-24gb`.
36. **Mac shape service.** Hunyuan3D-2.1 runs outside ComfyUI on the Mac (`mac/shape_server`, the VladimirTalyzin/hunyuan3d-2.1-mac MPS fork) behind `SHAPE_URL`; it is single-view, so `mac-m4pro` sends the front view only. The hy3dmlx MLX port could not be located and is not used.
37. **Tunnel.** Each Mac service listens on localhost only; Caddy (`mac/Caddyfile`, written-order `route`, bearer token) fronts them on one port and a Cloudflare tunnel exposes that port. The adapters send `Authorization: Bearer $GENAI_TOKEN` on every call.
38. **Model pins.** `models.yaml` pins repo, file, Hugging Face revision and size (checked against the Hugging Face API). Superseded in part by 42: the SHA256 values are now written up front from Hugging Face's metadata rather than on the host. ComfyUI, its node packs and the MPS fork are pinned to their commits as of 2026-10-28.
39. **MinIO image.** MinIO stopped publishing community images in October 2025; the stack uses Chainguard's free MinIO build pinned by digest (`minio` RELEASE.2026-10-23T20-06-51Z).
40. **Compose split.** `infra/docker-compose.yml` runs api, worker (arq), postgres, redis and minio for every profile; `infra/docker-compose.nvidia.yml` adds ComfyUI, Ollama and the worker's GPU reservation for `nvidia-24gb`. The app image takes an optional `build_ca` BuildKit secret for builds behind a TLS-inspecting proxy (empty by default).
41. **Deterministic Mac setup.** Everything `mac/setup.sh` installs is pinned in the repo and checked before use: tools (uv, Ollama, Caddy, cloudflared) as exact releases with SHA256/512 in `mac/tools.lock`, CPython 3.11.17 through the pinned uv, every Python package `==`-pinned with hashes for macOS 15+ arm64 and wheels only (`mac/locks/*.txt`, `uv pip sync --require-hashes`), and four code checkouts at commits. Homebrew is dropped (the Xcode Command Line Tools are the only prerequisite). The fork's `install.sh` is not run because it clones Tencent's Hunyuan3D-2.1 at HEAD, `git pull`s it on re-runs and installs unpinned torch; `setup.sh` does the same steps from pins. `mac/lock.sh` resolves with a fixed `--exclude-newer` date, so re-locking is reproducible; it runs in the VM because it installs nothing.
42. **Weight pins up front.** `scripts/models.py --pin --from-hub` writes each file's SHA256 (from Hugging Face's LFS metadata at the pinned revision; small non-LFS files are read and hashed) into `pipelines/comfy/models.lock.json` and the entry's SHA256 into `models.yaml`. No weights are downloaded, so the pins are committed before any host exists. A host's `--fetch` hashes each file as it downloads and keeps nothing that differs. Only `repo: local` entries (the S4 LoRA) are pinned on the host with `--pin`.
43. **Ollama model pin.** Ollama cannot pull by digest, so `models.yaml` pins the tag's manifest digest (`sha256:845dbda0…`, read from registry.ollama.ai) and `setup.sh` compares it with `/api/tags` after the pull; a moved tag fails the setup. Ollama checks each layer against the manifest itself.
44. **Shape on the Mac reads only the DiT folder.** Hunyuan3D-2.1's `hunyuan3d-dit-v2-1/model.fp16.ckpt` holds the DiT, the VAE and the DINOv2 conditioner (built from the config's inline DINOv2 settings), so the Mac fetches neither `hunyuan3d-vae-v2-1` nor `facebook/dinov2-*` (the fork's paint pipeline needs DINOv2-giant; the Mac textures by projection). The shape server sets `HF_HUB_OFFLINE=1` and fails with 503 rather than downloading when the weights are missing.
45. **Octree 192 on the Mac.** The MPS fork measured 30 steps at octree 192 in 5.7 min on an M4 Pro (7.6 s per step). Octree 256 has 2.4x the voxels (about +2.5 min) for surface detail that stage E's wrap onto the base topology smooths away. Expected per-pet time is revised from 8-12 to 12-16 min.
46. **hy3dmlx not used.** `AgenticVibes/hy3dmlx-shape-v2.1` (MLX weights of the same model) exists, but its loader package is neither public on GitHub nor on PyPI, and its published 12.9 s per step on an M3 Ultra is slower than the MPS fork's 7.6 s on an M4 Pro.
47. **No torchaudio in the ComfyUI venv.** Its newest macOS wheel (2.11) does not match torch 2.13; ComfyUI does not require it and no PetPop workflow uses audio.

## Two apps, one core (refactor after M2.5, BRIEF Section 17)

48. **Python packages live in `packages/<name>/python/`.** `petpop_core` (paths, schemas, breeds, vocab, spec merge, rule parser, manifest, prompt compiler and its Jinja templates) and `petpop_library` (base-mesh geometry `meshkit`, accessories, per-vertex colouring; later delta extraction, QC, release packer and loader). The TypeScript side of each package sits beside it in `src/`. Imports resolve through one bootstrap in `backend/__init__.py` (any entry point that imports `backend` can import both packages) plus `PYTHONPATH` in the Makefile, gates, `make dev`, Playwright and the Docker image, and pytest's `pythonpath`. Blender's `run.py` adds the paths itself because bpy runs without the backend's environment.
49. **What stays in `backend/`.** The API contract (pydantic models and the shared router factory) moves from `backend/core` to `backend/api` (it is the API, and the mock server already imports from `backend`). `backend/core` keeps the backend runtime: settings, GenAI profiles, the low-fidelity stand-ins and the runtime switches (`paths.mode()`, `mock_speed()`, `bpy_python()`), which read the GenAI profile and so cannot live in a package.
50. **npm workspaces and a fourth package.** The repo root is an npm workspace (`packages/core`, `packages/viewer`, `packages/ui`, `apps/kiosk`, `apps/studio`) with one lockfile. Packages export TypeScript source (no build step); the apps' Vite configs dedupe React and three. The brief names three packages; shared touch UI (frame, tiles, swatches, chips, keyboard, theme CSS) goes in a fourth, `@petpop/ui`, rather than being copied into both apps. The generated API client and types live in `@petpop/core` (both apps use them). Static assets go through `assetUrl()` so the same viewer works at `/` (kiosk) and `/studio/` (studio).
51. **API 2.0.0 layout.** Meta routes stay at `/api/v1` (`health`, signed `files`, the public result page `r/{token}`); the kiosk surface is `/api/v1/kiosk/*` (`sessions`, `breeds`, `bespoke`, `ops`) and the studio surface `/api/v1/studio/*` (`auth/login`, `auth/me`, `breeds`, `spec/parse`, `jobs`, events, `tweak`, `fulfil`, `retry`, `queue`). `/spec/parse` is studio-only: the kiosk never reaches an LLM. Browsers cannot set headers on a WebSocket, so the studio token goes in the events URL's `token` query parameter.
52. **Staff auth.** Local accounts in `staff_users` (scrypt hashes); `POST /studio/auth/login` returns an HMAC-signed bearer token (12 h) carrying the username and role; roles rank operator < curator < admin. Every studio route needs operator for now; curator and admin gates arrive with curation and publish (M8). Accounts come from `PETPOP_STUDIO_USERS` (`name:role:password;...`), else one account per role sharing `PETPOP_STUDIO_PASSWORD` (a random dev value under `var/` if unset, like the other secrets). The mock server accepts operator, curator and admin with `PETPOP_STUDIO_PASSWORD`, default `petpop-dev` (it holds no real data). The kiosk's five-tap panel keeps the LAN PIN (`PETPOP_STAFF_TOKEN`).
53. **Bespoke from the kiosk before compositions exist.** `POST /kiosk/bespoke {session_id, spec, contact?}` (403 unless `KIOSK_BESPOKE=1`) enqueues a `bespoke` job on the studio queue and returns a ticket and "we'll message you"; one per session (409 after). The optional contact is purged with free text after 7 days. M7 adds `POST /kiosk/compositions/{id}/bespoke` per Section 16. Studio jobs have no per-session cap (the three-run cap was a kiosk rule).
54. **Two queues.** `jobs.queue` (`kiosk` | `studio`) and `jobs.kind` (`pipeline` | `bespoke` | `export`); the local bus claims per queue, one job at a time per queue; arq uses `petpop:studio` and `petpop:kiosk` with `StudioWorkerSettings` and `KioskWorkerSettings`; Compose runs `worker-studio` and `worker-kiosk`, and the NVIDIA GPU reservation moves to `worker-studio`. Only the studio worker builds adapters; importing the worker loads no real adapter (tested). A job of the wrong kind on a queue is failed, not run. There are no database migrations in the PoC: after pulling this change, delete `var/` (and the Compose Postgres volume).
55. **The kiosk between the refactor and M7.** Attract, Species, Breed, then a Design screen that shows the breed preset on the base mesh until the library tools land; "Make it unique" sits on Design. Gate 1 now runs one walkthrough per app: the studio walkthrough is the old Generate journey behind a sign-in, the kiosk one ends at Design or "Make it unique".
56. **Studio UI.** Same portrait frame and UI kit as the kiosk (simplest; it also runs on a desktop browser), real text inputs on the sign-in screen, no idle wipe, a top bar with the user, the queue and sign-out. The phone result page stays in the kiosk app, which serves `/r/*`.
57. **CLAUDE.md is Section 15's text verbatim.** It drops two lines the M2.5 follow-up had added (`mac/lock.sh` and the "Mac setup is fully pinned" ownership rule); the deterministic Mac setup itself is unchanged and documented in `mac/RUNBOOK.md` and items 41 to 44.

## M7: kiosk library mode (BRIEF Section 16)

58. **Proxy library from the base meshes' own shape keys.** `scripts/make_proxy_library.py` builds `fixtures/library/release-{dog,cat}-1.tar` with no GenAI. Each region part is the base mesh's shape keys for one preset enumeration value (`vocab.json` maps values to weights), cut to its region by `region_weights` and feathered by the vertex-group weights: dog 4 families, 24 region deltas; cat 3 families, 19. The five shell parts are the accessory library on its neck, head and face sockets; the ten pattern layers come from `petpop_library.patterns`. `CREATED_AT` is fixed, so a rebuild is byte-identical. Studio replaces this content in M8 through the same bundle format.
59. **Pattern masks are rank-normalised fields, not literal signed distances.** Each pattern is a scalar field over the surface: distance from its core (the chest from the body front, the socks from the floor, the points from the extremities), plus value noise for tabby, brindle and merle. The field is rank-normalised over the pattern's allowed region to 0..250, so coverage c covers a fraction c of that region and the slider moves the edge at a steady rate; texels outside the region hold 255 and are never covered. The shader and the export threshold at `coverage * 250` with a 2-level soft edge. The masks are 1024², packed four channels per RGBA PNG; the eye and nose masks fill the last two channels of the third file.
60. **Stamps are stored in base-mesh space and rasterised per triangle.** A stamp is `{p, r, colour}` in millimetres on the undeformed base mesh: the kiosk maps a hit back through the hit triangle's barycentrics. So a stamp stays put when parts change, and it paints every triangle its sphere touches, whichever UV island holds it. That is what makes a stamp across a UV seam land correctly. The edge is feathered over 0.5 mm, stamps composite "over" in order, and the layer is quantised to 8 bits. The TypeScript rasteriser is a line-for-line port of the Python one and matches it byte for byte (golden test). Both sides grow the stamp layer 2 texels into the UV padding so bilinear sampling never reads an empty texel at a seam. Limits: 400 stamps and 10 layers per composition; spots are 3, 5 or 8 mm, the brush 1.5 mm.
61. **Symmetry writes the mirrored stamp explicitly** (`x -> -x`, skipped within half a radius of the midline), so the composition alone reproduces the print. Undo removes the last stroke: one tap, or one brush drag.
62. **Compositing order and maths are shared.** Base colour, then the pattern layers in order, then stamps, then nose, then eyes, all in 0..255 floats quantised with `floor(x + 0.5)`. The kiosk's GLSL (`PatternMaterial.ts`) and `petpop_library.paint.composite` implement the same function. Gate 7 bakes the shader into an RGBA8 target and compares it with the export's render of the same composition, texel for texel.
63. **The preview is the final asset.** The kiosk loads the release's `base.bin` (positions, triangles, corner UVs, shell ids), applies the family and region deltas by summation, exactly as `petpop_library.deltas.compose` does for the export, and splits vertices at UV seams for three.js. Shells sit on sockets placed from the composed mesh's landmarks. Deltas are little-endian float16, decoded on the kiosk.
64. **Release format and trust.** A release is a tar of `manifest.json`, `manifest.sig` (HMAC-SHA256 of the manifest bytes) and every listed file with its sha256. The key is `PETPOP_RELEASE_KEY`; unset, both sides use a published development key, which is what the committed proxy releases are signed with. A production kiosk sets its own key and so refuses dev-signed bundles. HMAC rather than public-key signing keeps the PoC dependency-free; Studio and Kiosk are run by the same operator.
65. **Release loading.** At start the API installs, oldest first, every bundle in `PETPOP_RELEASE_INBOX` (default `var/releases/inbox`; Studio drops bundles there in M8) that is newer than the active release, then re-checks every 30 s. A fresh kiosk also loads the committed proxy releases unless `PETPOP_SEED_PROXY_LIBRARY=0`. Installed releases live in `var/releases/<species>/<version>/`. The switch is an `os.replace` of the `ACTIVE` pointer, so readers see the old release or the new one, never half of either. The last two are kept, so an order placed just before a switch still exports. A release whose base topology differs from the kiosk's base mesh is refused.
66. **Kiosk library API (3.0.0).** The brief's paths sit under `/kiosk`: `GET /kiosk/library/{species}` (the active release: its manifest and files URL), `.../families`, `.../parts?region=` (`ears`, `tail`, `muzzle`, `head`, `legs`, or `shells`), `.../patterns`, and `.../files/{path}` (only files the manifest lists). The composition routes are `POST /kiosk/compositions`, `GET /kiosk/compositions/{id}`, `POST .../export` (202 and idempotent; it issues the ticket) and `POST .../bespoke`. `POST /kiosk/bespoke {spec}` from the refactor is removed: "Make it unique" now saves the design as a composition and sends that to the studio (Section 16), whose `to_spec` turns it into the bespoke job's starting PetSpec. The breaking change is why the version is 3.0.0.
67. **Export without AI.** An export is a `kind=export` job on the kiosk queue whose spec carries the composition. The kiosk worker loads the release the composition names, composes the deltas, renders the albedo at atlas size with `petpop_library.paint` and upscales it to the profile's `albedo_px`, then runs the print half of Stage F, factored out as `stage_f.finish_export` and shared with the pipeline. That half fuses the shells through the accessory path, adds the base and mandrel socket, and runs the print and paint checks, GLB, thumbnail and turntable. Finally it copies the print bundle plus `composition.json` to `fulfilment/<ticket>_<job>/`. The manifest's new optional `source` block names the composition and release, and its `genai` block records "none (library export)". Measured at the profile's print quality: about 37-39 s per species with 10 layers, 400 stamps and a shell.
68. **The order is the composition.** `compositions` rows hold the JSON as the order record. Their export state is the export job's (draft, exporting, ready, failed), and the ticket is issued at export. The five-tap ops panel lists the last 20 orders and can reprint one, which copies its bundle to the fulfilment folder again. Syncing orders to a Studio orders table is later work (Section 17).
69. **Library tables.** `families`, `region_deltas`, `shell_parts`, `pattern_layers` (versioned items keyed by id and version, with status draft/accepted/rejected/published, files, tags, QC metadata, source job and batch) and `curation_batches` are the Studio's library, which M8 fills. The kiosk never reads them; it reads only its installed bundles (Section 17: the kiosk reads nothing else from Studio).
70. **Starting composition.** A breed starts on the family that lists it (else `family_standard`) and on the parts whose tags match its preset's enumeration values. Its preset colours become the base colour, its pattern and markings become the first layers, and its nose and eye colours carry over, all in `apps/kiosk/src/lib/compose.ts`.
71. **Design screen.** One screen with a live preview above four tabs: Shape (Body plus a chip per region, parts as thumbnail tiles), Markings (coat colour, ten pattern tiles, a slider and swatches per active layer), Paint (spot sizes, brush, colour, mirror, a "turn figure" toggle so a drag can rotate instead of paint, undo, dab count) and Extras (accessories, one per socket, with colours; eye and nose colours). Then Name, then Order: a progress bar until the export finishes, then the ticket and QR. A coverage change only writes a uniform and re-renders its own layer row (about 1.5 ms per update, no texture uploads). Gate 7 measures that instead of frame rate, because CI renders with software GL.
72. **Gate 7 runs on the mock profile.** The real backend's export uses Blender on CPU, so no GenAI host is needed. "With the GenAI host unreachable" is tested by pointing the `mac-m4pro` profile at `127.0.0.1:9` for both the export timing script and the real-backend walkthrough. The kiosk still completes the order because its worker builds no adapter.

## M8: Studio curation and releases (BRIEF Sections 16 and 17)

73. **A batch is jobs, not a new runner.** `POST /studio/batches {species, breeds, variants, seeds}` creates a `curation_batches` row and one `kind=batch` job per breed × variant × seed on the studio queue (at most 60 per batch). Each job runs the full pipeline, A to F, so every figurine has a GLB and a turntable for review. Then the studio worker curates it. Variants are PetSpec patches applied over the breed preset; the builder offers six (preset, big ears, stocky, slim, long tail, short muzzle), and seeds count up from 1.
74. **Extraction inverts the composition exactly.** `part_r = D * w_r / max(1, Σw)` for the five regions, and `family = D - Σ part_r`, where D is the wrapped figurine minus the base mesh. So a figurine's family plus its five parts recomposes it to float16 precision (≤ 0.002 mm on the fixture pack), and a part carries only its region's offsets. The brief's "full-mesh family delta" is therefore the body that remains once the regions are taken out.
75. **QC metrics.** Each metric is reported per region and for the family.
    - Wrap validity: Stage E's `wrap_valid`, and a parametric or unwrapped fallback counts as invalid. An invalid wrap rejects everything.
    - Symmetry error: mean distance in mm between a delta and its X mirror (through a nearest-vertex mirror map of the base), weighted by the region.
    - Boundary strain: 95th-percentile relative change in edge length in the region's feather band when the part is applied to the bare base.
    - Self-intersection: crossing triangle pairs within a shell, found with a KD-tree on triangle centroids and an edge-through-triangle test, counted per region by vertex. Crossings the base mesh already has are subtracted: the proxy cat base has 12.
76. **Auto-reject thresholds** are symmetry over 3.0 mm, boundary strain over 2.0, or any new self-intersection. Tails are exempt from symmetry, since curled and sickle tails are asymmetric by design. The thresholds were calibrated on the fixture pack, which is real pipeline output on the mock profile: clean pets pass every region, and the folded brachycephalic muzzles of gus and mochi, plus a few leg crossings, are rejected. A curator can still accept an auto-rejected part, and the metric stays visible.
77. **Item life cycle.** Items are keyed by (id, version, species), because ids such as `shell_collar` repeat across species. Statuses run draft → accepted or rejected → published → superseded. Editing a published item creates the next version as a draft; publishing it supersedes the previous published version and regenerates the thumbnail (for patterns, the preview at the default coverage). Unpublish returns an item to accepted. Candidate ids are `<region>_<breed>_<job prefix>` and `family_<breed>_<job prefix>`. Studio starts from the proxy release, imported as published version 1, so its first release is `release-<species>-2`.
78. **A parts set** is a figurine's family plus at least four of its five region parts, all published. Gate 8's yield criterion (at least 15 parts sets from 20 figurines) counts these.
79. **Releases.** `POST /studio/releases {species}` needs the admin role. It packs the latest published version of every family, region part, shell and pattern, plus `base.bin`, `mesh.json` and the atlas masks, with the shared `petpop_library.packer`. It then stores the bundle, writes it atomically into the kiosk inbox, and records it in `library_releases`. A release is refused while a region has no published part. A family's default part that is not published falls back to the first published part of that region. A kiosk on the same box loads the release at once; others pick it up within 30 s.
80. **Roles.** Operators run jobs and batches and browse everything. Curators review, edit, publish and unpublish. Admins pack releases.
81. **Studio screens.** Login lands on Generate, the batch builder; the old Build, Brief and Name flow is the "One-off figurine" path (bespoke jobs). The top bar switches between Generate, Review, Library and Releases. Review shows a card per figurine with its turntable video, then one row per candidate with its QC line, accept, reject and a ★ "hero" tag, and publish. "Fix in Blender" is a documented round-trip (download the GLB, edit it on the base topology, re-run it as a one-off), not a tool.
82. **The mock server curates for real.** Its Studio side is the backend's `StudioLibrary` on a private SQLite database and store. Batch figurines "finish" on a script with a fixture pet's real pipeline output, then curation, QC, publish and packing run unchanged, so both implementations pass the same contract test. A mock release also switches the mock kiosk.
83. **Gate 8 on the mock profile.** It covers:
    - the curation unit tests;
    - Contract 1;
    - the Studio library contract test on both implementations;
    - the studio screen tests;
    - `scripts/gate8_clean_kiosk.py`: a real batch on the stand-ins is published and released; a second install with no proxy library loads only that bundle and exports a composition built from the new family and parts;
    - the curation walkthrough against the real backend.

    The yield criterion needs a GenAI host and prints SKIPPED (`scripts/gate8_yield.py`).

## Before S3

84. **The shape server queues meshes as jobs.** Cloudflare ends any proxied request after about 100 s (HTTP 524), on both quick and named tunnels, and a Hunyuan3D-2.1 mesh takes about 6 minutes on the M4 Pro. So the shape API now works like ComfyUI's prompt queue:
    - `POST /v1/shape` validates the request, checks that the weights are present (503 at once if not), queues the job and answers `202 {job_id}`.
    - One worker thread runs jobs in order, which keeps one model resident.
    - `GET /v1/shape/{id}` reports queued, running, done or failed; `GET /v1/shape/{id}/mesh` returns the GLB.
    - `/v1/free` never blocks: during a run it unloads afterwards.
    - Finished jobs are kept for an hour.

    The adapter submits, polls every 3 s and downloads, with every request capped at 30 s. It tolerates up to 5 consecutive failed polls (a tunnel blip) and gives up at the stage deadline. The old handler also ran the model inside an `async` route, which blocked even `/health` for the whole run; the job thread removes that too. The fake GenAI host logs every request's duration, and the profile test asserts that none takes more than 30 s.
85. **Named tunnel as the recommended path.** RUNBOOK §4 leads with the named tunnel: a free Cloudflare account, a domain on Cloudflare, three one-time `cloudflared` commands, and `CF_TUNNEL` / `CF_HOSTNAME` in `~/petpop-genai/genai.env`, so `make -C mac tunnel` always serves the same hostname. The quick tunnel (no account, random hostname per start) stays as the fallback.
86. **Concept without proxy-mesh control.** The S3 sweep (docs/s3/2-concept-sweep.png) showed the img2img init from the proxy's flat render and the depth ControlNet make the concept look procedural. Plain txt2img at 1024 (c3) gives the best breed recognisability; weak depth (strength 0.35 to 35 %) is the fallback if stage D needs a predictable pose. The style comes from the LoRA, not from IP-Adapter style references, which overwrite breed identity.
87. **No white-canvas start.** Starting from a white canvas at denoise 0.92 gives white backgrounds but shrinks the subject and turns some breeds into line art (docs/s3/3-concept-white-canvas.png). Backgrounds are fixed after generation by a background-removal model instead of the `white_key` colour key.
88. **Per-view SDXL views ruled out for the library.** Depth ControlNet plus IP-Adapter per view trades identity against viewpoint and never draws a back (docs/s3/4-views-per-view-sdxl.png). Multi-view generation (MV-Adapter) is the library path; whether the kiosk keeps per-view views or uses front-only texture is decided after the MV-Adapter test.
89. **MV-Adapter and Hunyuan3D-2mv on the Mac.** ComfyUI-MVAdapter at its pinned commit, with current diffusers (0.42) instead of its own 0.31 pin, which ComfyUI's transformers rules out. SDXL as a diffusers fp16 folder saved under the plain file names (`models.yaml` `rename`), because its loader passes no variant. Hunyuan3D-2mv (and the 5-step turbo) run through ComfyUI's built-in nodes; the MPS fork has no 2mv support and is not needed.
90. **Folders by relative path.** `mac/setup.sh` links `ComfyUI/petpop-models` to the model root, so workflows name `petpop-models/<dest>` and never an absolute host path.
91. **Model root in genai.env.** `PETPOP_MODELS` is read from the environment, then `~/petpop-genai/genai.env`, then `~/petpop-models`, by both `setup.sh` and `mac/Makefile`; setup keeps the file in step.
92. **DINOv2-Large as an embed service.** Image embeddings (view consistency, best-of-N, LoRA curation, library search) are their own GenAI service in the profile (`EMBED_URL`, Caddy `/embed/*`), served for now by the shape server's process so they share its one-model slot. Clients never call the shape service for them, so the model can move to its own process by changing only the profile and the proxy.
93. **Sweep scores.** The white-border score alone rewards blank images; every view set is also scored for subject fill (share of the frame unlike the border colour) and DINOv2 similarity to the concept, with front/back similarity as a check that the back is not a copy of the front.
94. **Golden seed not pursued.** A seed's effect does not carry across prompts, settings or the LoRA; seeds are fixed only for evaluation. Best-of-N with an automatic score is the alternative, after the LoRA.
95. **MV-Adapter without VAE slicing.** ComfyUI-MVAdapter's model makeup node calls `pipeline.enable_vae_slicing()`, which diffusers 0.42 (decision 89) no longer has on pipelines, so workflow 02b sets `enable_vae_slicing` off. Four 768 px views decode in one batch, which fits the Mac's 24 GB; if memory runs short, the node can be patched to call `pipeline.vae.enable_slicing()` instead.
96. **Left and right are the pet's own.** Checked on the Mac: MV-Adapter's azimuth 90 draws the pet's left side (nose toward image left), and Tencent's Hunyuan3D-2mv example `left.png` images face image left too, matching `meshkit` (left = camera at +X). Workflow 02b now maps batch index 1 to `view_left` and 3 to `view_right` (docs/s3/5-views-mvadapter-scored.png); 03 takes the views unchanged.
97. **Reading the DINOv2 view scores.** Similarity to the concept mixes identity with viewpoint: a face-on "back" scores as high as a true side view, so it judges a view set only together with front/back similarity (a real back scored 0.52 to 0.69, a copied front 0.87 to 0.92) and the left/right balance (one side far above the other means it is under-rotated, e.g. 0.88 against 0.64). For best-of-N concepts, which share the front viewpoint, similarity alone is usable. Subject fill is reliable on smooth backdrops only; textured floors count as subject (docs/s3/5-views-mvadapter-scored.png), so it is measured after matting once a background-removal model is in place.
