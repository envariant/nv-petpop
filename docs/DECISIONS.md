# Decisions

Choices made where BRIEF.md is silent or ambiguous. Newest at the bottom.

1. **Branch.** The cloud session is pinned to branch `claude/serene-darwin-imby77`; it plays the role CLAUDE.md gives `poc`. Each milestone is also pushed as a snapshot branch `milestone/mN` with a PR against `main`, so every milestone gets its own PR while work continues.
2. **Proxy base meshes moved into S0.** The fixture pack (S0) and the Build-screen preview (S1) both need the base meshes, so `scripts/make_proxy_base.py` and `scripts/check_base_mesh.py` are built first.
3. **Python layout.** One project venv (`.venv`, Python 3.12) for API, worker, mock server and tests. Blender scripts run as subprocesses under the bpy interpreter (`PETPOP_BPY_PYTHON`, default `/opt/bpy/bin/python`, Python 3.11 + `bpy` 5.0), mirroring the production "Blender via subprocess" design. Shared contract models and the rule-based parser live in `backend/core/` and are imported by the mock server.
4. **Rendering engine.** Workbench and EEVEE need EGL/GPU and crash headless; all mock renders use Cycles on CPU at low samples.
5. **PetSpec enumerations.** Closed sets chosen where Section 3 lists none: body.size tiny/small/medium/large, build slim/standard/stocky, a 12-name coat palette (custom hex maps to the nearest name), 12 patterns (the Build screen shows the 8 that fit the species), markings white_blaze/white_socks/white_chest/dark_mask/points, 6 eye colours, 5 nose colours. `overrides` only allows `ears.asymmetry`. `ears.tufted` (cat) drives the `ear_tuft` morph.
6. **Cat morph list (spec gap).** Section 10 says "cat: 12, no brachy split, add ear_tuft", which does not add up from 15. Chosen: drop `brachy`, `ear_drop`, `tail_curl`, `leg_len`, add `ear_tuft` (12). `vocab.species_substitutes` maps the dropped dog targets onto cat ones. To confirm with whoever builds the hand-made cat mesh.
7. **Morph weights** range -1..1 with 0 = the base mesh; slot contributions are summed and clamped. `ears.asymmetry` is prompt-only in the PoC (no per-side morph exists in Section 10).
8. **Units.** Base meshes, wraps and print meshes are in millimetres (1 Blender unit = 1 mm), 90 mm tall; GLBs keep those units and the viewers fit the camera to the bounds.
9. **Region masks.** Pattern and marking regions are baked once per base mesh into two UV-space RGBA masks (`mask_a.png`, `mask_b.png`). The preview shader, the mock renders and the albedo bake read the same masks, so swatches, preview and output agree.
10. **One contract router.** `backend/core/contract.py` defines every `/api/v1` route once against an implementation protocol; the mock server and the backend mount it, so their OpenAPI is identical by construction and `data/schema/openapi.json` is generated from it (`make openapi`), with a drift check in gate-0.
11. **Mock script selection.** The mock server picks a script by pet name (`Slowpoke`, `Oops`, `Plan B`), otherwise `MOCK_SCRIPT` (default `normal`), so every kiosk state is reachable from the touchscreen with no headers.
12. **Fixture pack v1** is produced by the numpy/trimesh stand-in (`make_fixtures.py --lowfi`, `fidelity: low`); S2 regenerates it from the real mock-mode pipeline. About 32 MB.
13. **GPU gates.** Gates 3 to 5 exit 0 after printing `gate-N: SKIPPED (needs GPU)` in mock mode and never print PASSED; gate-6 likewise skips (needs the kiosk screen and GPU).
14. **MSW parser.** Standalone mode (`VITE_MOCK=1`) uses a small TypeScript synonym matcher over `vocab.json` instead of the Python rule parser; it is only for demos without a backend.
15. **Visual directions.** Three Storybook themes over the same components, selected with the toolbar (kiosk: `?theme=`): `candy` (default: warm paper, orange dog / violet cat accents, 36 px radius), `studio` (neutral greys, tight radius, product-shop feel) and `toybox` (dark indigo, saturated yellow/teal, chunky shadows). The kiosk ships `candy` until the touch review picks one.
16. **Build layout.** Portrait 1080x1920: selectors scroll in a left column, the live preview is a fixed 400 px column on the right, labelled "Preview". The preview albedo is painted on a 256 px canvas from the UV region masks (same rules as the bake) and the morph weights come from a TypeScript port of `morph_weights`; both update in well under 100 ms.
17. **Kiosk frame.** The SPA renders a fixed 1080x1920 canvas scaled to the window; R3F canvases measure with `offsetSize` so the CSS scale does not shrink the drawing buffer. Tests run at 540x960 with touch enabled.
18. **Idle policy overrides.** `?idle=&countdown=` (seconds) override the session's idle policy for tests and demos; production uses the API's 90 s + 15 s.
19. **Attract loop content** comes from the bundled fixture pack (the first six pets), so the attract screen works with no API call; S5 can swap in real demo figurines.
20. **Fixture GLBs are Y-up** (glTF convention, front +Z), matching the Blender exporter; print meshes stay Z-up in millimetres.
21. **make dev queue and events.** The brief pairs "two Python processes" with "in-process asyncio queue + fakeredis", which cannot span processes. `LocalBus` uses the SQLite `jobs` table as the queue (atomic claim of the oldest queued row, one running job at a time) and a `job_events` table that the API tails for WebSockets. `RedisBus` (arq + Redis lists) implements the same interface for the GPU host. `PETPOP_EMBED_WORKER=1` runs the worker thread inside the API process (tests, smoke runs).
22. **Stage signature.** Stages are `run(job_id, spec, manifest, *, ctx)`: the brief's `(job_id, spec, manifest)` plus a keyword-only context carrying the store, adapters, progress callback and settings. Stages read inputs only through `ctx.get()` (the artefact store) and write through `ctx.put()`.
23. **Quality profiles.** `PETPOP_PROFILE` = `full` (brief values: 1024/768 px, 2048 albedo, 0.15 mm voxels, 250 k tris), `dev` (default in mock mode, ~45 s per job on 4 CPU cores), `fixture` (fixture pack, ~3 MB per pet) and `test` (contract, pipeline and regression tests). Mock-mode stage timeouts are the brief's times 6 because Blender runs on CPU.
24. **Mock texture source.** In mock mode the views are renders of the same flat colours, so the mock texture backend paints the PetSpec colours over the region masks in the fixed UV layout instead of projecting the views. Per-region colour correction toward the PetSpec hex values runs on generated textures (real mode).
25. **Wrap details.** Coarse fit = ICP (similarity) + landmark pull propagated with an RBF (the Surface Deform role); fine fit = shrinkwrap by projection along normals (both directions, 3 mm limit) on the body shell only, three passes of rising strength. Ears and tail keep their morph shape with a rigid fit (Section 14 mitigation). Validation is relative to the morphed template (the wrap must not add self-intersections). Multires is not used on the ~6 k-quad proxies.
26. **Blender container.** The worker image bundles the `bpy` wheel (Python 3.11) and runs the Blender stages as subprocesses with Cycles on CUDA, instead of a separate `blender` service; the compose file therefore has api, worker, comfyui, ollama, postgres, redis, minio.
27. **Print mesh.** Shells, accessories and the base disc are joined, voxel-remeshed, the socket is cut with exact booleans, decimated, then cleaned (merge, fill pin-holes, drop loose fragments < 0.5 %); a trimesh repair pass removes boolean slivers before STL/3MF. Accessories are thickened in the library so nothing prints under 1.5 mm, and the collar sinks slightly into the neck.
28. **Proxy morph fixes.** `leg_len` stretches everything below the leg tops continuously (no fold), `fluff` pushes along smoothed normals by 1.8 mm, and tail roots sit inside the body so the print is one solid. These are proxy-only; the hand-built meshes define their own shape keys.
29. **Fixture pack v2** is regenerated by the real mock-mode pipeline with the `fixture` profile; intermediates (control renders, wrapped mesh) are pruned to keep it near 30 MB.
30. **Accessory UVs.** Accessories carry their own small UV islands but are flat-coloured materials in the GLB; `figure_uv.obj` (the painter layout) contains the pet only.
